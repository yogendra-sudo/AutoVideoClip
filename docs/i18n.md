Do not maintain duplicate pages under `.github/README.md` or `.github/README-EN.md`. GitHub may prefer the `.github` README and make root-directory updates invisible on the repository homepage. See [GitHub README rules](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes). Keep only the maintainer email in README contact information; do not add messaging-service contacts or QR-code entry points.

Installation, Docker, and troubleshooting guides are available in English. Translate other detailed technical documentation as needed. README language variants are maintained separately from application UI, subtitle, and model language capabilities.

## Update Procedure

1. Synchronize README feature, installation, and configuration changes in the same pull request.
2. Keep commands, filenames, model names, parameters, download links, and badge URLs unchanged.
3. Use `/releases/latest` for downloads and derive platform information from actual release assets. Do not encode a current version, Stars, Forks, or Issues number in badges.
4. Verify implementation and release records before documenting a new platform, feature, or export option.
5. Run `python3 scripts/check_readmes.py` and `git diff --check` from the repository root.
6. Review the page, language entries, tables, and images in GitHub Markdown preview.

Synchronize version notices, CLI/MCP ZIP links, and wheel filenames for each release and verify them against the public release assets. `scripts/bump_version.py` updates runtime versions and CHANGELOG only. Link first-run, signing, and acceptance status to the corresponding release and installation guide. Keep model availability aligned with the actual provider catalog.

The `I18n Documentation Sync` workflow checks local links, image links, code fences, and badges across the README variants. It does not modify files or automatically translate content. External badges are not CI network dependencies.
